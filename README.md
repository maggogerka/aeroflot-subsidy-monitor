# Aeroflot Subsidy Monitor

Локальный монитор субсидированных билетов Аэрофлота для Windows. Он открывает
видимый Chromium, заполняет официальную форму, проверяет заданную
последовательность дат и сообщает о появлении билета через Telegram и громкую
локальную тревогу.

> Проект не связан с ПАО «Аэрофлот». Он не покупает и не бронирует билеты, не
> вводит платёжные или паспортные данные и не обходит CAPTCHA. Интерфейс сайта
> может измениться — перед длительным запуском обязательно выполните один
> контрольный цикл.

## Возможности

- любая программа из поля «Программа субсидирования»;
- любое доступное на сайте направление;
- перелёт в одну сторону или туда-обратно;
- произвольная последовательность дат, включая повторы приоритетной даты;
- произвольные типы и количество пассажиров по их подписям на сайте;
- выбор класса обслуживания;
- два режима обновления страницы;
- строгая классификация `AVAILABLE / UNAVAILABLE / UNKNOWN` без догадок;
- Telegram с повторными попытками и повторными напоминаниями;
- непрерывная локальная тревога с ручным подтверждением;
- постоянный профиль Chromium для cookies и ручного прохождения CAPTCHA;
- журнал, heartbeat, безопасные диагностические снимки и атомарное состояние;
- защита от одновременного запуска двух экземпляров.

На момент последней проверки форма сайта содержала программы «Дальний Восток»,
«Пассажиры с инвалидностью», «Многодетные семьи», «Молодежь и пенсионеры»,
«Жители Калининградской области» и «Учащиеся ВУЗов Калининградской области».
Список не зашит в программу: в конфигурации используется точная подпись сайта.

## Требования

- Windows 10/11;
- Python 3.11 или новее;
- работающий интернет;
- Telegram-бот — если нужны Telegram-уведомления;
- ноутбук не должен переходить в спящий режим.

## Быстрый старт

Откройте PowerShell в папке проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
.\scripts\configure.bat
.\.venv\Scripts\python.exe -m app.main --test-alert
.\scripts\run_once.bat
.\scripts\run_monitor.bat
```

Установщик создаёт `.venv`, устанавливает зависимости и Chromium, копирует
локальные `.env` и `config.yaml`. Мастер настройки спрашивает программу,
маршрут, даты, обратный билет, пассажиров и уведомления. Секретный токен вводится
скрыто и сохраняется только в игнорируемом файле `.env`.

## Настройка вручную

Скопируйте `config.example.yaml` в `config.yaml` и измените секцию `route`:

```yaml
route:
  subsidy_program: "Молодёжь и пенсионеры"
  origin: "Москва"
  destination: "Владивосток"

  check_dates:
    - "2026-08-29"
    - "2026-08-30"
    - "2026-08-29"

  trip_type: "one_way"       # либо round_trip
  return_date: null           # для round_trip: "2026-09-07"
  cabin: "Эконом"

  passengers:
    "Молодёжь": 1
```

Названия `subsidy_program`, `cabin` и ключи `passengers` должны совпадать с
видимыми подписями формы. Различие `е/ё` учитывается автоматически. Несколько
типов пассажиров задаются так:

```yaml
passengers:
  "Взрослый": 1
  "Ребёнок": 2
```

Не каждая программа допускает любой маршрут, класс или тип пассажира. Если
сайт не показывает указанную строку, монитор возвращает `UNKNOWN` и не сообщает
о билете как о найденном.

### Перелёт туда-обратно

```yaml
trip_type: "round_trip"
return_date: "2026-09-07"
```

Обратная дата должна быть не раньше каждой проверяемой даты. Реальный сценарий
выбора обеих дат покрыт автоматическими тестами и проверен на живой форме.

### Порядок и обновление дат

`check_dates` — именно последовательность, а не множество. Повтор даты разрешён.

```yaml
monitoring:
  refresh_mode: "cycle"
```

- `cycle`: в начале цикла обновить страницу и заполнить форму для первой даты,
  затем переключать остальные даты в свежей ленте результатов;
- `date`: полностью обновлять и заполнять форму перед каждой датой.

Паузы задаются диапазонами — фактическое значение выбирается случайно:

```yaml
monitoring:
  min_cycle_delay_seconds: 240
  max_cycle_delay_seconds: 420
  min_date_delay_seconds: 8
  max_date_delay_seconds: 20
```

Не уменьшайте интервалы агрессивно: это повышает риск ограничения со стороны
сайта и не гарантирует более свежий результат.

## Telegram

Создайте `.env` из `.env.example`:

```dotenv
TELEGRAM_BOT_TOKEN=123456:ваш_токен
TELEGRAM_CHAT_ID=ваш_chat_id
```

Как получить `TELEGRAM_CHAT_ID`:

1. Создайте бота через `@BotFather` и отправьте своему боту любое сообщение.
2. Откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`.
3. Возьмите число из `message.chat.id`.
4. Выполните тест:

```powershell
.\.venv\Scripts\python.exe -m app.main --test-alert
```

При `AVAILABLE` сообщение отправляется сразу. При временной ошибке выполняются
повторные попытки, затем напоминания через интервалы из `config.yaml`. Абсолютная
доставка невозможна при выключенном ноутбуке, отсутствии питания или интернета.

## Громкая локальная тревога

При обнаружении билета начинается непрерывный чередующийся сигнал и появляется
системное окно поверх остальных окон. Следующая проверка не отключает тревогу.
Остановить её можно кнопкой «ОК» либо:

```powershell
.\scripts\stop_alarm.bat
```

Предварительная проверка:

```powershell
.\scripts\test_alarm.bat
```

Громкость регулируется Windows. Перед ночным запуском выберите динамики
ноутбука, отключите беззвучный режим и установите достаточную громкость.

## Команды

| Команда | Назначение |
|---|---|
| `.\scripts\configure.bat` | интерактивная настройка |
| `.\scripts\run_once.bat` | один полный цикл |
| `.\scripts\run_monitor.bat` | постоянный мониторинг |
| `.\scripts\stop_monitor.bat` | остановить экземпляр по PID-файлу |
| `.\scripts\test_alarm.bat` | проверить локальную тревогу |
| `python -m app.main --test-alert` | проверить Telegram |
| `python -m app.main --diagnose` | сохранить безопасную диагностику |

## CAPTCHA и ошибки

CAPTCHA не обходится. При её появлении монитор делает длительную паузу,
оставляет браузер открытым и отправляет предупреждение. Решите CAPTCHA вручную.

`UNKNOWN` означает, что программа не получила достаточно независимых признаков
для безопасного решения. Это намеренное поведение: лучше сообщить о проблеме
распознавания, чем разбудить пользователя из-за обычной цены в календаре.

Журнал находится в `logs/monitor.log`. Скриншоты ошибок — в `artifacts/`. Полный
DOM, cookies и localStorage в диагностические файлы не сохраняются.

## Безопасность данных

В репозиторий не должны попадать:

- `.env` и Telegram-токен;
- `config.yaml` с личным маршрутом;
- `browser_profile/`, cookies и состояние браузера;
- `logs/`, `artifacts/`, `monitor_state.json` и `.monitor.pid`;
- `.venv/`.

Эти пути уже перечислены в `.gitignore`. Перед публикацией всё равно проверьте
`git status` и `git grep`.
